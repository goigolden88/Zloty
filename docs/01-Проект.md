# Проект

Обновлён: 19.09.2026

## Зачем

Вносить месяц денег за минуты, а не копированием листа, и сразу видеть ответ на вопрос «сколько я откладываю и хватает ли дохода» — вместе с тем, что в этом месяце вышло за обычное (Р-07).

## Проблема

Почти год человек каждый месяц руками ведёт таблицу Excel. Файл — личные данные, в репозиторий не попадает; разбор на самих данных — в Этапе 0 (Р-02, Р-11). Сейчас — со слов человека:

1. **Ручной ввод и копирование.** Лист месяца во многом — копия прошлого; повторяется же только часть — связь, интернет, автосигнализация. «Дефолтные» траты переписываются руками из банковского приложения
2. **Разрозненные листы.** Расходы, ценности, инвестиции, «Основная выжимка», персональная инфляция, необходимый доход — отдельными листами, связанными руками
3. **Нет ответа.** Таблица не отвечает ни «куда уходит», ни «хватает ли дохода», ни «какова моя инфляция» — та же поломка, что у таблицы еды («Трапеза», 01-Проект, «Проблема», п. 7)
4. **Смысл — в комментариях.** «Регулярные за январь учтены в прошлом периоде», «траты на медицину за мамин счёт — не учтены», особые траты — с датой и описанием в комментарии. Формулы их не видят
5. **Дробные суммы.** В таблице встречается `4205,584973` — след пересчёта дробными числами
6. **Нестандартные слова.** «Пассивы» — ценности (крипта, валюта, счета), «активы» — инвестиции. В приложении с модулем долгов это путаница (Р-05)

Листы таблицы:

- **Расходы по периодам** — строка — период (обычно месяц, бывает «11.12–11.01»); «Регулярные», «Дефолтные» (из банковского приложения), «Особые траты» (дата и описание в комментарии), сумма, комментарий
- **Инвестиции** — по датам: сумма на каждой площадке (Т-Инвест, Альфа-Инвест, Jetland, Polymarket, прочее), итог, % к прошлому шагу, формула сложного процента
- **«То, что приносит доход или хранит ценность»** — по датам: крипта (mBTC), USD, EUR, наличные ₽, банковские счета ₽, прочее, курс, итог в USD и в ₽
- **«Основная выжимка»** — по датам: «пассивы», «активы», сумма, расходы за последний месяц, комментарий
- Ещё — персональная инфляция, запланированные расходы (ещё не ведётся), необходимый доход из средних потребностей

## Границы

**Делаем:** учёт доходов и расходов операциями и итогами периода; регулярные шаблоны; норма сбережений, обычный месяц, рост обычного месяца, необходимый доход; долги — комнаты и одноразовые; сбережения и вложения снимками по датам с курсами; несколько валют; local-first, работа без сети, синхронизация устройств, экспорт без замков; импорт своим форматом по промпту для беседы с Claude.

**Не делаем:** аккаунты, бэкенд, общие комнаты с другими людьми (Р-01, вариант Б — отложен); вызовы Claude API из приложения — он платный, продукт тестируется бесплатно; разбор выписок внутри приложения — он в беседе (Р-08); портфели, ребаланс, API брокеров сейчас (Р-09 — дорога не закрыта); бюджеты-лимиты по категориям; остаток счёта, выведенный из операций (Р-05); автозапись регулярных (Р-06); подключение к банкам.

## Ядро (общее для модулей)

- **Одна дверь в данные извне — `zloty-import`** и экран импорта в каждом модуле; формат одинаково выдают беседа сейчас и бэкенд или брокер потом (Р-08, Р-09)
- **Деньги целыми** в минимальных единицах с кодом валюты; итоги — в базовой валюте данных по курсу на дату (Р-04)
- **Число — с основанием** (Р-07)
- **Словарь** — Р-05
- Лента с поиском, экспорт и импорт файла-копии, «Что нового», справка с числами из констант, работа без сети, синхронизация в фоне — механика ядра `FamilyCore` (Р-03)
- Напоминание «пора внести месяц» — своя тема поверх напоминаний ядра

## Модуль «Учёт» — Этапы 1–2

- **Счёт** — где лежат деньги, одна валюта на счёт; **категории** расходные и доходные (Р-05)
- **Операция** — расход, доход, перевод между своими счетами; **итог периода** там, где операций нет; итог позже раскладывается на операции (Р-02)
- **Особая** трата — флаг: во всех расходах есть, в обычном месяце нет (Р-05)
- **Регулярные** — шаблоны, «Внести» тапом, выписка отмечает сама; «за какой период» — поле операции (Р-06)
- **Экран «Месяц»:** доход, расход обычный и особый, отложено, норма сбережений, «вышло за обычное» (Р-07)
- **Этап 2:** необходимый доход, рост обычного месяца, отчёт «что улучшить» — markdown месяца и промпт для беседы (Р-07)

## Модуль «Долги» — Этап 3

- **Ведёт один человек** — «казначей»: комнаты, участники, траты («заплатил один, поровну на N»), переводы, «вернул», минимизация переводов, итог друзьям текстом (Р-01)
- **Одноразовые долги** — «дал Пете», «взял у Маши», возврат частями (Р-01)
- **Люди** — один справочник на всё; «сколько мне должен Петя» — по всему сразу
- **В учёт — только своя доля;** возврат — не доход, заём — не расход (Р-05)
- Модель комнаты — такая, чтобы позже в неё могли писать участники по ссылке (Р-01, шесть условий)

## Модуль «Капитал» — Этап 4

- **Сбережения** (счета, наличные, валюта, крипта) и **вложения** (площадки) — счета двух видов (Р-05)
- **Снимок** — сколько было на счёте на дату; остаток из операций не считается (Р-05)
- **Курсы** на дату: руками, импортом, позже — публичный источник (Р-04)
- **Капитал** = сбережения + вложения + мне должны − я должен, в ₽ и USD, % к прошлому снимку (Р-07)

## Распространение

Режим по умолчанию — данные в браузере, без синхронизации, перенос файлом-копией: посторонний, открывший `goigolden88.github.io/Zloty/`, получает работающее приложение и никакой сети. Синхронизация — опция для того, кто заведёт приватный репозиторий данных и токен.

Стартовых категорий и счетов в коде нет: у друга свои, заводятся руками или импортом. Базовая валюта — свойство данных (Р-04). Отдача другу — вместе с остальными приложениями семьи (как Этап 7 «Трапезы»).
