### Подмодуль ядра

С Этапа 0 (Р-03).

- **Клон** — только `git clone --recurse-submodules`; склонированное без него — `git submodule update --init`. Иначе `src/shared` пустая, и сборка падает непонятной ошибкой
- **`src/shared` отсюда не правится.** Ядру чего-то не хватает, в нём ошибка, `db` или `sync` не подходят под его типы без `as` — сказать человеку, что и где, дать промпт для сессии сопровождения `FamilyCore` (шаблон — в её `06-Процесс`) и остановиться на этом месте
- **Обновление ядра здесь** — `git submodule update --remote src/shared`, затем тесты, сборка, прогон по коду выхода и **коммит указателя**. Видимое изменение ядра — строка в `src/changes.ts` в том же коммите
- **Перед пушем** — `git status` чистый **и в подмодуле тоже**: `git -C src/shared status`
- **В `src/shared` не запускать `npm install`** — вторая копия React (Я-02 «FamilyCore»)
- **Тесты ядра здесь не гоняются, типы — проверяются** — как Р-52 «Трапезы»: `vitest` исключает `src/shared/**`, `tsc` проверяет его целиком
- Поломка в ядре чинится один раз, в `FamilyCore`

## Разделение работы

**Claude Code — и «что строить», и «как».** Продуктовые развилки и пересмотры архитектуры — тоже здесь: он видит настоящие файлы и проверяет факты. Режим планирования — когда обсуждаем и ничего не трогаем.

**Чат (Claude Desktop, claude.ai) — когда компьютера нет под рукой**, для свободного разговора без кода и для картинок. Итог приходит в репозиторий готовыми кусками markdown.

**Беседа с Claude — ещё и инструмент данных.** Выписки, скриншоты и файлы разбираются вне приложения по его промпту; в приложение приходит готовый JSON `zloty-import` (Р-08, Р-09). Выписки из беседы в репозиторий не кладутся — только в `seed/`.

### Планирование в Claude Code

1. Сессия планирования из корня репозитория — заготовка в «Шаблонах»
2. Решения — в `05-Решения` в момент выбора; правки `01`, `02`, `03` — по ходу
3. Конец: Журнал, передача, коммит документов, дерево чистое
4. `/clear` — и код новой сессией по плану. Контекст планирования в неё не переезжает: память — документы

## Обратный поток: код → обсуждение

То, что Claude Code в конце сессии называет «не описано в документах», возвращается в обсуждение, а не решается на месте.

## Правила ведения документов

- **Не менять задним числом.** Отмена решения — новая запись со ссылкой
- **Решения записываются в момент выбора**
- **Журнал обновляется в конце каждой сессии**
- **Перед пушем — `npm test`, `npm run build`, `npm run smoke`**, итог по коду выхода, а не по выводу
- **Прогон проверяется порчей**, когда меняется его сценарий: сломанная строка экрана обязана дать код 1. Порча — в `git worktree`, не в основной папке
- **Worktree порчи получает `node_modules` ссылкой-junction** — и перед удалением ссылка снимается первой (`cmd /c rmdir <worktree>\node_modules`), только потом `git worktree remove`. `--force` по живой ссылке вычищает зависимости основной папки (Журнал 23.09.2026)
- **Видимое изменение — строка в `src/changes.ts`** в том же коммите
- **План содержит только предстоящее**
- **Цифра с листа таблицы — вместе с формулой**, из которой она посчитана (опыт «Трапезы», Журнал 15.09.2026)
- **Правки файлов с кириллицей и замены с обратной косой чертой** — инструментом правки или скриптом-файлом из папки сессии, не heredoc Bash: он съедает `\` (опыт `FamilyCore`, Журнал 18.09.2026)
