# Архитектура

Обновлён: 19.09.2026
Версия схемы данных: 1 (ещё не выпущена)

**Состояние документа.** Модель учёта здесь — **контур**, а не окончательные типы: форма записи учёта решается по выгрузкам банков в начале Этапа 0, до кода (Р-02, Р-11). Всё, что помечено «контур», переписывается тогда же отдельным решением; остальное решено.

## Стек

- **Vite + React + TypeScript**, `strict` и `noUncheckedIndexedAccess` — настройки ядра, `tsconfig` — `extends: "./src/shared/tsconfig.base.json"`
- Роутинг через хеш (`#/month`), `HashRouter` — на GitHub Pages обычные пути дают 404 при обновлении страницы
- Сайт живёт по `/Zloty/` (Р-10): `base` в `vite.config.ts` равен имени репозитория, с ним согласованы `start_url`, `scope`, `id` манифеста, пути иконок и `navigateFallback`. Неверный `base` даёт зелёную сборку и белую страницу
- Стили — обычный CSS: каркас ядра `src/shared/styles.css`, поверх — свой `src/styles.css` с акцентом
- Хранилище — IndexedDB, синхронизация — приватный репозиторий GitHub; механика — ядра
- Service worker — `startWorker` ядра, свой — только тема напоминания; сборка `injectManifest` через `familyVite`
- **Ядро — `FamilyCore`, подмодулем в `src/shared`** (Р-03)
- Бэкенда нет. Платформа — PWA

## Два репозитория

| Репозиторий | Что внутри | Видимость |
|---|---|---|
| `Zloty` | исходники, сборка, GitHub Pages | публичный |
| `ZlotyData` | JSON-файлы данных | приватный |

Pages для приватного репозитория требуют платного тарифа, поэтому код публичный. Секретов в нём нет по определению. Токен вводится руками в настройках и живёт только в браузере; у каждого устройства свой.

## Модель данных

`Base` — из ядра (`shared/core/model.ts`), договор семьи: `id` (ULID), `updatedAt`, `deleted?`. Своей не заводится.

### Деньги — решено (Р-04)

```ts
// Сумма — целое число в минимальных единицах валюты: 123456 RUB = 1 234,56 ₽.
type Money = {
  amount: number               // целое; знак — у операции, не у суммы (контур, Этап 0)
  currency: CurrencyCode
}

// ISO 4217 для фиатных: 'RUB', 'USD', 'EUR'; знаков — из Intl.NumberFormat.
// Крипта — таблица в коде: 'BTC' — 8 знаков (сатоши). Больше 8 знаков не бывает.
type CurrencyCode = string

// Курс на дату: 1 from = rate to. Дробный — законно: пересчёт не хранится.
type Rate = Base & {
  date: string                 // ГГГГ-ММ-ДД
  from: CurrencyCode
  to: CurrencyCode
  rate: number
  source: 'manual' | 'import' | string   // публичный источник — позже, своим именем
}
```

- **Пересчёт — чистая функция**, результат округляется при показе и нигде не хранится
- **Какой курс:** операция — на дату операции; снимок — на дату снимка. Нет курса на дату — ближайший более ранний не старше `RATE_MAX_AGE_DAYS`; нет и такого — позиция вне итога и названа числом
- **Единица показа** — свойство валюты в интерфейсе: BTC хранится в сатоши, показывается в mBTC
- **Базовая валюта и вторая валюта показа** — свойство данных, синхронизируются (контур: запись `profile`, ниже)

### Справочники

```ts
// Где лежат деньги. Одна валюта на счёт (Р-05).
type Account = Base & {
  name: string                 // «Т-Банк карта», «Наличные», «Т-Инвест», «BTC кошелёк»
  currency: CurrencyCode
  kind: 'savings' | 'investment'   // сбережения / вложения (Р-05)
  archived?: boolean
  order: number
}

// За что потрачено или откуда пришло. Расходные и доходные — разные (Р-05).
type Category = Base & {
  name: string
  side: 'expense' | 'income'
  archived?: boolean
  order: number
}

// Регулярная — шаблон, который сам ничего не пишет (Р-06).
type Recurring = Base & {
  name: string                 // «Связь», «Интернет», «Страховка ОСАГО»
  categoryId: string
  accountId?: string
  expected: Money
  every: { months: number }    // 1 — раз в месяц, 12 — раз в год, N — раз в N месяцев
  from: string                 // ГГГГ-ММ, с какого периода действует
  to?: string                  // ГГГГ-ММ, по какой; нет — действует
  order: number
}

// Свойства данных, общие для всех устройств (контур, Этап 0).
type Profile = Base & {        // одна запись, id 'profile'
  baseCurrency: CurrencyCode   // у него 'RUB'
  showCurrency?: CurrencyCode  // вторая валюта капитала, у него 'USD'
}
```

Id справочников — ULID или из названия, как `cat:<название>` в «Трапезе» (её Р-12), — решается в Этапе 0: из названия даёт слияние одноимённых с двух устройств без дублей.

### Записи учёта — контур (Р-02)

```ts
// Операция — или итог периода там, где операций нет (Р-02).
type Entry = Base & {
  kind: 'expense' | 'income' | 'transfer'   // transfer — между своими счетами: не расход и не доход
  accountId: string
  money: Money
  date?: string                // ГГГГ-ММ-ДД — операция
  period?: { from: string; to: string }     // итог периода: «11.12–11.01»
  categoryId?: string          // у transfer — нет; у итога периода — обязательна
  toAccountId?: string         // у transfer
  special?: boolean            // особая: во всех расходах есть, в обычном месяце нет (Р-05)
  recurringId?: string         // от какой регулярной (Р-06)
  for?: string                 // ГГГГ-ММ — «за какой период», только для блока «Регулярные» (Р-06)
  note?: string                // комментарии таблицы — сюда
  refs?: string[]              // связь с долгом или тратой комнаты — Этап 3 (Р-05)
}
```

Что решается по выгрузкам, в начале Этапа 0 — «Открытые вопросы» `05`: что считать счётом; итог периода на стыке месяцев — к какому месяцу сводок и файла; естественный ключ операции (номер операции банка, время); как отмечается перевод между своими счетами; знак суммы; валюты сверх четырёх.

### Снимки — Этап 4, форма известна (Р-05)

```ts
// Сколько было на счёте на дату. Не `Snapshot`: так в ядре называется файл-копия.
type Balance = Base & {
  accountId: string
  date: string                 // ГГГГ-ММ-ДД
  amount: number               // в валюте счёта, целое
  note?: string
}
```

### Долги — Этап 3, контур (Р-01, Р-05)

```ts
type Person = Base & { name: string; self?: true; archived?: boolean }   // «я» — человек с пометкой

type Room = Base & { name: string; currency: CurrencyCode; personIds: string[]; closed?: boolean }

// Кто заплатил, сколько, на кого делится. Доли — участники комнаты по id.
type RoomSpend = Base & {
  roomId: string
  date: string
  title: string
  payerId: string
  amount: number
  split: { personId: string; share?: number }[]   // нет share — поровну
}

type RoomTransfer = Base & { roomId: string; date: string; fromId: string; toId: string; amount: number }

// Одноразовый долг: «дал Пете», «взял у Маши».
type Loan = Base & { personId: string; direction: 'lent' | 'borrowed'; money: Money; date: string; note?: string }
type Repayment = Base & { loanId: string; money: Money; date: string }
```

Шесть условий Р-01 — обязательны при окончательных типах: комната самостоятельна; «я» — участник с пометкой; каждая трата и перевод — своя запись; долги и минимизация считаются, не хранятся; учёт читает комнату, а не наоборот; суммы целые. «Событие» комнаты и категория своей доли — открытые вопросы к Этапу 3.

### Правила модели

- **Потоки и остатки — два независимых взгляда** (Р-05). Остаток счёта — только снимок; из операций не выводится
- **Долги — не расход и не доход** (Р-05). Операция, связанная с долгом или тратой комнаты, входит в расход только своей долей
- **Обычный месяц** — средний расход за `USUAL_MONTHS` прошлых месяцев без особых (Р-07). **Норма сбережений** — (доход − расход) / доход; доход не внесён — так и сказано, а не ноль
- **На один счёт в одном периоде — либо итог, либо операции** (Р-02); импорт операций выводит итог и называет разницу
- **Всё посчитанное не хранится:** итоги, пересчёты, долги, обычный месяц
- **Стартовых категорий и счетов в коде нет** — у друга свои
- **`refs`** — связи между записями и, позже, между приложениями семьи: строка начинается с вида записи

## Раскладка данных в репозитории

Договор ядра: `meta.json`, справочник — одним файлом, записи — `<папка>/ГГГГ-ММ.json` по дате записи, `undated.json` — без разбираемой даты, `README.md` кладётся ядром (`src/shared/docs/02-Архитектура.md`, «Раскладка»). Своё — `places` конфига:

```
meta.json            { schemaVersion }
profile.json         базовая валюта — контур
accounts.json        счета
categories.json      категории
recurring.json       регулярные
rates/ГГГГ-ММ.json   курсы — по дате курса
entries/ГГГГ-ММ.json операции и итоги периода — по дате; месяц итога периода — Этап 0
balances/ГГГГ-ММ.json снимки — по дате
README.md

Долги — хранилища и строки раскладки миграцией Этапа 3. Нарезка по месяцам: обычный месяц с выпиской — сотни операций, порядка 100 КБ; годовой файл уезжал бы целиком с каждым изменением.

## Хранение на устройстве

База **`zloty`** — свой `dbName` на общем origin `goigolden88.github.io` рядом с `dnevniki`, `deluvremya`, `trapeza` (Р-10). Не меняется никогда.

**`v1Stores` — хранилища учёта и снимков** (Р-11): `profile`, `accounts`, `categories`, `recurring`, `rates`, `entries`, `balances` — контур, окончательно в Этапе 0. После первого релиза заморожен. Хранилища долгов — первая миграция, Этап 3. Индексы сверх `updatedAt` — по дате у `entries`, `rates`, `balances`; прочие — Этап 0.

Локальные хранилища ядра — `meta`, `settings`, `dirty`; `settings` не синхронизируются никогда — там токен. Ключи `settings` — ядра (синхронизация, «Что нового», сворачивание, напоминания, журнал ошибок); свои появятся с поводом и будут записаны здесь.

## Синхронизация

Механика — ядра `FamilyCore` (`shared/core/sync.ts`): local-first, грязные записи, проход через пять секунд после действия, при открытии и возврате сети; сначала влить чужое, потом отправить своё, одним коммитом. **Слияние — по записи, побеждает поздний `updatedAt`**, надгробия не вычищаются (договор семьи). Подключается в Этапе 1 (Р-11).

Файл-копия — механика ядра: `{ schemaVersion, exportedAt, data }`, все синхронизируемые хранилища с надгробиями, `settings` не входит.

## Импорт — договор (Р-08, Р-09)

**Единственная дверь в данные извне.** Любой источник — беседа с Claude сейчас, свой бэкенд или брокер потом — производит этот формат и проходит ту же проверку, сводку и кнопку. Никто не пишет в хранилища и в репозиторий данных напрямую.

```
{ "format": "zloty-import", "version": 1,
  "categories": [...], "accounts": [...], "entries": [...], "rates": [...],
  "balances": [...] }
```

- Без `id` и `updatedAt`; ссылки — по названиям: счёт, категория, человек; недостающее заводится
- **Суммы — в обычных единицах:** `"amount": 1234.56, "currency": "RUB"`; в минимальные — приложение; лишние знаки округляются и называются в сводке
- Каждое поле проверяется; кривая запись не попадает в базу и называется с причиной. До записи — сводка, запись — по кнопке. JSON принимается и в блоке ```` ```json ```` с текстом вокруг — механика ядра
- **Только добавляет**; совпавшее по естественному ключу пропускается. **Исключение — итог периода**, который заменяют операции того же счёта и периода: выводится, разница называется (Р-02)
- **Промпт знает справочники:** текущие категории, счета и регулярные вписываются в промпт из базы
- **Экран импорта — свой в каждом модуле:** `ImportRecords` ядра с разбором и промптом этого модуля; промпт — `buildPrompt` ядра из разделов модуля (Р-03)
- Разделы разбираются по порядку — справочники, потом записи, — каждый видит заведённое предыдущими
- Операции загружаются на одном устройстве; остальные получают их синхронизацией (Р-21 «Трапезы»)
- Поля и пример каждого раздела — в `modules/<модуль>/import.ts`; из них собирается промпт, тест прогоняет примеры через свою проверку. **Примеры выдуманные:** промпт уезжает к каждому
- **Формат меняется только добавлением;** старая `version` принимается и после изменений

**История таблицы** — через промпт приложения в сессии Этапа 1: Claude Code читает xlsx из `seed/`, собирает JSON, проверка сводит суммы по периодам со столбцом «сумма» таблицы (Р-08). Файлы — только в `seed/`.

**Как файл доезжает до приложения** — вставкой и файлом. «Входящие» в репозитории данных и запрос к брокеру из браузера — решениями, когда появится первый такой источник (Р-09).

## Как «Злотые» подключают ядро

Чеклист ядра (`src/shared/docs/02-Архитектура.md`, «Как приложение подключает ядро») писался под переезд. Для нового приложения — Этап 0:

1. `git submodule add https://github.com/goigolden88/FamilyCore.git src/shared`; в `deploy.yml` у `actions/checkout` — `submodules: true`. В `src/shared` `npm install` не запускается
2. `src/app/model.ts` — типы, `StoreRecord`, `SCHEMA_VERSION = 1`, `migrations = []`; `Base`, `Migration` — из `shared/core/model.ts`
3. `src/app/config.ts` — `AppConfig<StoreRecord>`: `name: 'Злотые'`, `dbName: 'zloty'`, `importFormat: 'zloty-import'`, `about` — строки о деньгах; `about.sources` обязан покрыть все экраны импорта (Р-03, «Цена» п. 4)
4. `src/app/core.ts` — `createDb`, `createSync`, `createLayout`, `createImporting`
5. `app.tsx` — `<CoreProvider value={{ config, db, sync }}>`, `<Layout tabs={TABS} />`
6. `useWhatsNew(base, CHANGES)`, `useFirstRun(own)`, `useFeed(feedItems)`, `<ImportRecords planImport importPrompt intro onChanged />` — в каждом модуле свой; `listenErrors(db.settings)` в `main.tsx`
7. `src/changes.ts` — список `CHANGES`; `Change` — из `shared/screens/changes.ts`
8. `src/notify.ts` — `createReminders(db.settings, { topics, idle })`
9. `src/sw.ts` — `startWorker({ remind })`
10. `src/styles.css` — после `shared/styles.css`, свой акцент
11. `vite.config.ts` — `familyVite({ base: '/Zloty/', name, description, shortcuts })`; `tsconfig.json` — `extends`; `scripts/icons.mjs` — свои фигуры
12. Своего объявления `__BUILD_TIME__` и `periodicSync` не заводить — они в `shared/vite-env.d.ts`

Чего нет, потому что переезда нет: прежних констант, открытия прежней базы, коммита-переезда.

## Договор семьи

Живёт в `FamilyCore` (Р-51 «Трапезы»). Чем «Злотые» обязаны: `Base` — из ядра; `FeedItem` — строки ленты собирает `registry.ts`; раскладка — `meta.json`, справочники одним файлом, записи по месяцам, своя таблица `places`; своя `schemaVersion` и миграции. Правка договора — релиз ядра на все приложения, не правка здесь.

## Версионирование схемы

`schemaVersion` — в `meta.json`, с первого дня; миграции пишутся сразу, свежая база доезжает до текущей теми же шагами. Первая миграция — хранилища долгов, Этап 3, `additive: true`. Устройство на старой версии, увидев схему новее в репозитории, останавливает синхронизацию со словами «обнови приложение».
